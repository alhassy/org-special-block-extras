* Overview

~org-special-block-extras-graph~ extends [[https://alhassy.github.io/org-special-block-extras][org-special-block-extras]] with a
~#+begin_graph~ block that compiles native Org syntax — nested plain lists and
two-column tables — into [[https://graphviz.org][Graphviz dot]].

No raw dot required.  Nesting encodes edges; inline tables encode attributes.

** Setup

#+begin_src emacs-lisp
(require 'org-special-block-extras)
(require 'org-special-block-extras-graph)
#+end_src

Graphviz must be on your ~PATH~ (~dot -V~ should work in a terminal).

** Pressing =C-c C-c=

Anywhere inside a ~#+begin_graph … #+end_graph~ block, ~C-c C-c~ renders a PNG
immediately.  The output filename is auto-generated unless you supply ~:file~:

#+begin_example
#+begin_graph directed :file my-diagram.png
…
#+end_graph
#+end_example

* Syntax Reference

| Construct                         | Dot equivalent                       |
|-----------------------------------+--------------------------------------|
| ~#+graph:~ table                  | ~graph [ … ]~                        |
| ~#+node:~ table                   | ~node [ … ]~                         |
| ~#+edge:~ table                   | ~edge [ … ]~                         |
| ~#+rank: n1 n2~                   | ~{ rank=same; n1; n2 }~              |
| ~#+cluster: id "Label"~ + table   | ~subgraph cluster_id { … }~          |
| ~+ NAME~ list item                | node ~NAME~ declaration              |
| ~∣ cluster ∣ id ∣~ on a node        | node belongs to that cluster         |
| indent ~+ CHILD~ under ~+ PARENT~ | edge PARENT → CHILD                  |
| ~∣ EDGE ∣ attr-string ∣~            | arc attrs — N rows = N parallel arcs |
| ~∣ id ∣ alias ∣~                    | cross-reference name for this node   |
| ~∣ to ∣ target ∣ attrs ∣~           | explicit outgoing edge (3-col)       |
| ~∣ key ∣ value ∣~ (other keys)      | node attribute                       |

1. If I press `C-u C-c C-c` I want to see the generated dot/graphivz code and not the png.
   - Add a `:C-c_C-c [png|dot]` option so that users can do `#+begin_graph :C-c_C-c dot` if they
     always want to see dot code; otherwise default is `png`.
     
2. When I go to the table and I see `| id | functor |`, I'm not sure what other key-value properties
   are there. So let's make `C-u RET` on a table introduce a new `|key | value |` interactively:
   A completion menu appears with a list of possible keys, then another menu for the list of possible values!
  - All node attributes can be found at https://graphviz.org/docs/nodes/
  - We can keep track of attributes in a new defcustom `graph-attributes` where each entry is of the form
    `(:name "label" :description "Text label attached to objects, any HTML valid string." :values nil ;; <- this means user has to enter some raw string
    :valid-on (edges nodes  graphs clusters) ;; <- this means we only show this attribute via `C-u RET` when the object being considered is one of these 
   )
